- İlk migration: `supabase/migrations/0001_source_layer.sql`

- Son migration: `supabase/migrations/0087_assistant_conversations.sql`
  - `764b0b543fccf44c4a33b140f4d21ae0077025ffa853530a5e391ab23420a9a1`
- Manifest dosyasının kendi SHA256'sı:
  - **`f70de82b4d269c3df477db03c963a96b2b793ba755ed918c57013cdf886f495d`**

Manifest kasten deterministiktir: içinde zaman damgası **yoktur**, çünkü zaman damgası manifestin
kendi hash'ini her üretimde değiştirir ve "aynı ağaç → aynı hash" doğrulamasını imkânsız kılar.
Aynı checkout üzerinde komut iki kez çalıştırıldı, iki kez aynı hash üretildi.

Bu hash'in kullanımı: cutover öncesi ve sonrası tekrar hesaplanır. Değişmişse migration ağacına
dokunulmuş demektir (P0 — schema migration checksum drift).

## 3. Yeniden üretim — hangi komut neyi üretir

Hepsi repo kökünden, POSIX kabuğunda (Git Bash / Linux runner) çalışır.

```bash
# 1. Commit
git rev-parse HEAD                       # -> 093573e30f451bb8857bed777352e80838e2e80e

# 2. Migration sayısı ve uç dosyalar
ls supabase/migrations/*.sql | wc -l     # -> 87
ls supabase/migrations/*.sql | head -1   # -> supabase/migrations/0001_source_layer.sql
ls supabase/migrations/*.sql | tail -1   # -> supabase/migrations/0087_assistant_conversations.sql

# 3. Migration manifest (deterministik — bu dosyayı birebir yeniden üretir)
printf '# MAS Nakit Radar - migration manifest\n# git-sha: 093573e30f451bb8857bed777352e80838e2e80e\n# algorithm: sha256, raw bytes, binary mode, LC_ALL=C sort by path\n# file-count: 87\n# reproduce: printf-header + ls supabase/migrations/*.sql | LC_ALL=C sort | xargs sha256sum\n' \
  > docs/release-evidence/migration-manifest.txt
ls supabase/migrations/*.sql | LC_ALL=C sort | xargs sha256sum \
  >> docs/release-evidence/migration-manifest.txt

# 4. Manifest hash
sha256sum docs/release-evidence/migration-manifest.txt
# -> f70de82b4d269c3df477db03c963a96b2b793ba755ed918c57013cdf886f495d

# 5. Workflow ve lockfile hash
sha256sum .github/workflows/ci.yml       # Faz 0 anı: 56635813...8587c
sha256sum pnpm-lock.yaml                 # c676108d...ea9f2c

# 6. Toolchain
node --version                           # -> v26.3.0
pnpm --version                           # -> 11.10.0
docker image inspect postgres:16 --format '{{index .RepoDigests 0}}'

# 7. Gerçek DB fingerprint — SALT OKUNUR, yazma yok
#    (kimlik bilgisi bu repoda yoktur ve buraya yazılmaz; operatörün .env.local'ından gelir)
#    select system_identifier from pg_control_system();
#    select max(version) from schema_migrations;
#    select count(*) from payments / checks / loans / cashflow_months / users;
```

**Gerçek DB'ye karşı yalnız `SELECT` çalıştırılır.** Bu belgedeki `real_db` blokunu üreten sorgular
orkestratör tarafından salt-okunur olarak alınmıştır; hardening branch'inde hiçbir script, fixture
veya migration `mas_radar_dev`'e bağlanmamıştır.
